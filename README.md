# University Institutional Analytics Dashboard

An institutional analytics platform covering **Admissions, Registrar, Finance, IT, Data Warehouse, Backend, Admin and Management**. It is built on the real UCI *Predict Students' Dropout and Academic Success* dataset, plus a clearly labelled synthetic institutional dataset that fills the features UCI lacks.

> **Data honesty rule:** every record carries `data_source` = `UCI`, `SYNTHETIC` or `EXTERNAL_REFERENCE`. Synthetic records are **demonstration data, not real university records**. UCI students are never mixed into the institutional (synthetic) population. All schools, programmes, calendars, fees and academic rules are **PLACEHOLDERS** until verified information is supplied.

**Current status (2026-11-11):**
- **Data:** synthetic data validated (476 / 476 checks).
- **Models:** 20 model tasks trained in **Google Colab** and backed up on Google Drive.
- **Application:** FastAPI backend and Refine dashboard working.

See [`docs/COMPLETION_REPORT.md`](docs/COMPLETION_REPORT.md) for what was verified.

## 2. UCI dataset inspection

| Property | Value |
|---|---|
| File | `data/raw/data.csv`, separated by `;`, UTF-8 with BOM |
| Rows / columns | **4,424 students × 37 columns**; 0 missing cells; 0 duplicate rows |
| Data types | 29 integer codes, 7 decimals, 1 text (`Target`) |
| Outcome `Target` | Graduate 2,209 (49.9 %) · Dropout 1,421 (32.1 %) · Enrolled 794 (17.9 %), measured at the end of the programme's normal duration |
| Programmes | 17 undergraduate course categories (Polytechnic Institute of Portalegre, Portugal) |
| Demographics | Female 2,868 / Male 1,556; 21 nationalities (Portuguese 97.5 %); age 17–70 |
| Performance | Units credited/enrolled/evaluated/approved and grade (0–20) for **semesters 1 and 2 of year 1 only** |
| Verified facts | The grade averages **passed units only**. Evening attendance = exactly programmes 8014 and 9991. `International` = nationality ≠ Portuguese. 180 students have 0 units in both semesters (75 of them graduated). 3 rows have "without evaluation" > "enrolled" |
| Quirks | Column `Daytime/evening attendance\t` has a trailing tab; `Nacionality` is misspelled (fixed only in processed copies) |

### What the UCI data can and cannot support
| Status | Features |
|---|---|
| ✅ **Available** | Gender, nationality, international flag, age at enrolment, marital status, UCI course category, day/evening schedule, application mode and order, previous qualification and grade, admission grade, scholarship / debtor / fees-up-to-date / displaced / special-needs flags, year-1 units and grades, final outcome |
| 🟡 **Partial** | GPA (0–20 average of passed units; not a true GPA) · performance trends (2 relative semesters only) · graduation (an on-time outcome only, with no date) · "school" (none) |
| 🔧 **Derivable** | Pass rate per semester · evaluation status (`NOT_EVALUATED`, `NO_UNITS_PASSED`) · a standing indicator (only once rules are defined) · outcome rates per course category |
| ❌ **Missing institutional features** | Student IDs, academic years and calendar terms, admission/graduation dates, schools, university programmes, Master's and Doctorate students, online vs face-to-face, full/part-time, course-level grades, multi-term histories, stop-outs, readmissions, programme changes, fees/payments/holds, user accounts/logins/servers |
| 🧪 **Requires synthetic generation** | Every missing feature above that the dashboard needs: enrolment per term/year/school, retention (Fall→Fall, Spring→Spring, Summer→Summer, cohort), 6/4/6-year graduation rates, time-to-degree, warning → probation progression, finance, IT and nightly-sync records |

**Dashboard support from real data:** demographics, enrolment by UCI course category, first-year performance and pass rates, and on-time outcome by course category. These appear in **separate UCI reference panels**. Everything time-based, postgraduate, financial or operational comes from synthetic data.

> UCI students never receive invented admission dates, semester histories, graduation dates, programmes, schools or university identities. They are stored only in `data/processed/uci/`.

## 4. The synthetic dataset (generated and validated)

**Scope:** 5,000 synthetic students first admitted between **Fall 2016 and Fall 2026**. Data as of **2026-11-10**. Spring and Summer 2027 exist in the calendar as **FUTURE** terms only (plus 320 pending/decided applications for Spring 2027).

| Area | Rows | Highlights |
|---|---|---|
| Admissions | 13,320 applicants · 13,600 applications | 5,000 first admissions + 154 next-degree + 126 readmissions; rejected/declined/withdrawn/waitlisted applicants never become students |
| Registrar | 5,556 programme admissions · 31,965 term enrolments · 112,408 course enrolments · 29,856 standing rows · 124 cohorts · 11,007 status events · 36,965 retention records · 5,154 graduation records | 276 programme transfers, 126 readmissions, 809 returns after a stop-out; 3,355 completed terms flagged for poor performance |
| Finance | 116,157 charge lines · 60,239 payments · 4,111 holds · 609 registration blocks | Holds are placed and released by rule; a held student cannot register until they pay |
| IT | 5,140 accounts · 134,387 login events (last 180 days) · 1,800 server-days · 76 incidents | Disabled accounts cannot log in successfully; outages cause failed logins |
| Data Warehouse | 720 nightly sync runs · 1 generation run | Every synthetic row carries `source_system` and `generation_run_id` |

**Headline metrics (synthetic demonstration values, not benchmarks):**
- **Final graduation rates (mature cohorts only):** Undergraduate 6-year 51.2 % (694 / 1,355) · Master's 4-year 64.0 % (472 / 738) · Doctorate 6-year 69.9 % (121 / 173). Windows are project-configured reporting assumptions; final cohorts are UG and Doctorate 2016FA–2020SU, Master's 2016FA–2022SU.
- **First-year cohort retention Fall 2025 → Fall 2026:** 85.2 % institutional (350 of 411), 83.0 % programme. Labelled **FINAL_CENSUS_SNAPSHOT**: the Fall 2026 census has passed but the term is still running.
- **Fall → Fall 2025→2026 (all enrolled):** 88.2 % retained of 1,715 eligible (2,046 enrolled − 331 graduates reported separately). **Spring → Spring 2025→2026:** 88.0 %. **Summer → Summer 2025→2026:** 28.1 % re-enrolled in Summer; **84.1 % continuation** (151 of the non-returners skipped the optional Summer and were enrolled in Fall 2026).
- **Spring 2026 → Spring 2027 and Summer 2026 → Summer 2027:** labelled **INCOMPLETE** (future terms).
- **Median time-to-degree:** UG 4.32 years · Master's 2.30 · Doctorate 3.32.

Full results: `data/synthetic/reports/data_quality_report.md` and `data/synthetic/reports/metrics/`.

### Known characteristics of the synthetic data (read before analysis)
1. **Warm-up period:** the simulation starts with no students before Fall 2016, so headcount grows from 298 (Fall 2016) and only levels off at about 1,800–2,100 from Fall 2022. **Early headcount growth is a simulation artefact, not a trend.**
2. **Summer→Summer re-enrolment is low (about 28 %)**; students who skip the optional Summer but enrol the next Fall are reported as `CONTINUING_SKIPPED_OPTIONAL_SUMMER`, never as stopped out or left because Summer study is optional. It is reported, but it isn't comparable with Fall→Fall.
3. **Historical status uses the complete recorded history**, e.g. a student is classified LEFT from the end of their last attended term.
4. GPA counts every graded attempt and **restarts for each programme admission**, including readmissions. Withdrawals carry no refunds. Each year uses the same calendar dates.
5. All distributions (grades, attrition, online share, payment behaviour) are **configurable assumptions** in `synthetic_config.toml`, chosen to look plausible. They are not calibrated to any real institution.

## 5. How to run (PowerShell, from the project root)

```powershell
cd data_warehouse
python -m pipelines.uci_processing             # 1. rebuild data/processed/uci/ (checks the raw file fingerprint first)
python -m pipelines.synthetic.generate         # 2. regenerate data/synthetic/ (about 2-3 min, seed from the config)
python -m pipelines.validation                 # 3. all checks + report (about 7 min; add --skip-repro for about 2 min)
python -m pytest -q                            # 4. automated tests incl. 30 planted-error tests (about 5 min)
cd ..
```
What each does: (1) reads the original CSV read-only and writes UCI-only tables. (2) Simulates every student term by term and exports all department tables. (3) Re-checks every rule with independent code, regenerates the data twice to prove reproducibility, and writes the quality report. (4) Runs quick regression tests.

Only the folders the generator owns (`reference/`, `admissions/`, `registrar/`, `finance/`, `it/`, `data_warehouse/`, `schema/`) are replaced on regeneration. Nothing else in `data/` is touched.

**Dependencies:** Python 3.12 with pandas and numpy (pytest for tests). They are already installed and listed in `data_warehouse/requirements.txt`.

## 6. Decisions made during implementation (documented assumptions)
The earlier open clarifications were resolved as follows. All can be changed in the config.

| # | Decision |
|---|---|
| C1 | 6 / 4 / 6 years are **graduation-rate windows** and **project-configured reporting assumptions** requested for this dashboard (the Doctorate window is not verified policy). Normal durations are separate placeholders (UG 4, Master's 2, Doctorate 4) |
| C2 | Two cohort types: **INSTITUTIONAL** (first admission to the university; for retention) and **LEVEL_ENTRY** (first admission at a level; for graduation rates) |
| C3/C4 | Admissions Fall 2016–Fall 2026 (per your instruction). As-of date 2026-11-10. Fall 2026 is **IN_PROGRESS** / `CENSUS_SNAPSHOT_ONLY` (census headcount and retention only; no grades, GPA, standing or graduations). 2027 terms are **FUTURE_NOT_REPORTABLE** |
| C5 | Summer entrants are measured at the next Summer **and** at the first Fall at least one year later (both labelled) |
| C6 | Readmission after withdrawal or dismissal is allowed, through a READMISSION application |
| C7 | Only missed Fall/Spring terms count as gaps. Summer is optional. More than 3 consecutive missed regular terms = UNOFFICIAL withdrawal recorded at the next census: **configurable synthetic business rule** `SYN-WD-MISSED-TERMS` (`academic.max_consecutive_missed_terms`), logged in `student_status_history`; the admission record is never overwritten |
| C8 | Cohorts can be filtered by level, delivery mode (online/face-to-face) and study load (full/part-time) |
| C9 | Synthetic gender categories: FEMALE, MALE, ANOTHER_GENDER, NOT_DISCLOSED (placeholder) |
| C10 | No concurrent enrolment in two programmes |
| Other | Home country = ISO user-assigned `ZZZ` ("home country not configured"). Currency USD (placeholder). Graduation date = end of the graduation term |
